# 最终报告


# 背景介绍

模型的部署，推理，训练存在许多领域的人工调优和问题定位的语料知识，寄希望于将这些领域知识注入到模型中，使得相似问题出现后，模型可以作为助手帮助能力定位，但是一个实际场景中的问题定位和性能优化，需要多方面的考量，因此需要模型具有多步推理能力 ，在该场景中，我们以晟腾中若干人员编写的实际业务中对模型的性能优化的案例，作为语料，尝试在qwen 3 8b中，将这些 能力注入到模型中

# 挑战

- 1.  数据匮乏： 我们只有若干原始的由开发人员编写的定位定界原始语料，其中存在图片信息无法利用 ，质量并不高，更没有高质量的问答数据
- 2. 无测试验证方法： 对于问题定位分析来说，没有统一的标准答答案，只能使用llm as judge  

- 3. 定位定界的方案不具有通用性， 属于长尾分布问题，不确定其是否存在共同内在维度表示


对于以上问题，本案例主要采用

- 1. 合成数据： 对原始语料采用高阶模型进行润色修复，并在此基础上采用两阶段(生成question -> 基于question生成答案） 的方式合成sft 和 dpo数据
- 2.  key_points 打分： 使用llm_as_judge，对于若干测试问题 ，每个问题的答案主要看是否命中若干key_points来作进行打分
- 3. 验证rl的能力提升



# 训练

我们采用三种训练方式
- cpt : 基于已有的案例语料对模型做继续预训练
- sft:   对语料中涉及的领域知识点 进行监督微调 帮助模型记忆领域知识点，
- dpo :   使用强化学习方式，考虑到 在对一个实际场景的性能问题 ，模型的回答难以通过规则方式判断优劣和对错，因此grpo无法使用，而训练一个打分模型又过于复杂，因此采用dpo （ 实际采用grpo也可以，使用一个高阶模型基于文档进行key points打分 不过训练资源有限，8b模型也只能做lora了，此外还考虑到奖励稀疏性 调优过于复杂）

###  **dpo** :

对于优劣答案构造： 考虑了两种方式，一种是直接生成优答案，并在优答案的基础上对其进行破坏（ 减少可能的解决方法，或朝着错误的问题定位方向 等）生成劣答案，一种是对原模型qwen3_8b 的回答进行采样，  在此基础上进行修正作为正负答案对。 
最终合成的数据集标签和方案如下: 


- **dpo_v3**:   采用glm生成问题，并直接合成对应的优劣数据，chosen数据为基于案例文档直接给出，reject 为在此基础上的推理步骤不完全，思考不全面 等方面 错误回答，chosen 和 reject 的token重合度上比较低
- **dpo_v5_stage_**1:  使用qwen3_8b生成问题回答（问题为sft数据集中的问题）作为reject， 使用qwen3_8b在给出该问题所对应的实际案例文档作为参考的回答作为 chosen 并要求对于rejected中的回复正确部分不要修改，从而使得chosen 和 reject重合度上较高
- **dpo_v5_stage_2**:  使用dpo_v5_stage_1中的chosen作为reject， 使用 glm4.6模型在给出该问题所对应的实际案例文档作为参考的回答作为 chosen   并要求对于rejected中的回复正确部分不要修改
- **dpo_v5_stage_3**:    dpo_v5_stage_1的reject作为reject,  dpo_v5_stage_2的chosen作为chosen

# 实践结果观察


- dpo数据如果都是chosen 和 reject 都是 ref model 中采样的，即自身，那么其reject和chosen在分化时候不明显 ，在所有的实验过程中，发现想要出现chosen上升，reject下降的理想训练结果，是不太容易的，更多的是 chosen上升，reject不变或者是chosen不变，reject下降 

- dpo 训练对学习率和数据敏感，建议逐批次训练，由易到难，且使用不同的学习率， 对于小模型+lora的话，建议提升学习率，否则会导致梯度过小，且epoch应该在1-3之内， 


- 如果dpo数据的chosen和reject 都是非ref model采样数据，容易过拟合和发生能力退化 


- 对于dpo阶段训练结果不理想的潜在解决方案
	-  1. reject 和 chosen 震荡没改变： 思考学习率问题

# conclusion
## dpo 或许不适合作为 提升模型推理能力的手段

从数据角度，dpo会出现使用dpo反而不直接采用dpo的数据直接做sft的效果差异，
从RL来说，dpo相比于grpo, ppo的离线策略的特征，很难控制模型学的是chosen数据的分布，还是真的理解到了reject 和chosen中的推理策略，还有分布偏移的问题（当然可以依靠细粒度的多次dpo ，逐渐提升难度和广度），但是这么做的数据合成会需要花很大的力气，


对于dpo 做训练，需要细粒度的数据构建
- 1. 构建更多的负例dpo
- 2. 从reject 回答到 chosen 回答 ，构建批次的难度差异


- 3. 批次训练，在token的差异上，应当逐渐减小，在采样来源上，应该逐批次进行，至于混合训练（结合pt和sft) 在本次实验中没有看到任何收益部分， 


此外，我们还需要做dpo训练和sft训练的对比， 在本次实验的训练上，如果以glm模型的答案作为优化目标和 提升测试集的准确率上，本次实验的发现是 ，dpo的训练结果不如直接使用 dpo的chosen做sft的效果，当然，sft可能是增加了模型的探索空间，但牺牲了其他方面的能力（这需要做额外的测试验证）  但dpo的性能上限由于其离线学习，策略空间低于grpo等问题，最终反映在提升测试集点数上不如直接用同样优化目标的chosen数据做 sft ( sft可以直接记忆一些能提分的点， 且没有KL散度的约束拖累) ， 



##  评估模型过于困难


仅通过cpt就可以实现，且不同的训练方式之前并没有拉开很大的差距（ 超过cpt结果的五个点以上） ，有一部分原因是因为其测试集本身就是基于语料的生成的，测试问题的key_points中就存在在语料之中，为了显现出dpo 和 sft的差异（ sft cpt依靠记忆就可以提升key-points）， 应当还需要在其他方面的 推理or定位问题的数据集上比较，以判断模型是否真的在推理能力上有进步， 




需要更细致的 多步的数据集合成路径： 
数据集构造的问题，可以从key points 角度入手，先由高阶模型基于语料生成该案例的定位定界步骤链，对于每一个步骤合成若干问题，对于每个问题生成若干chosen , reject 对，
